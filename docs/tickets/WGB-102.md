# WGB-102 · Verification of Payee

**Type:** Feature · **Priority:** High · **Component:** `src/payee.js` (new), transfer console

## Story

> "Since 9 October 2025, banks in the EU must check the name of the payee against the IBAN before a customer sends a euro transfer. We start with accounts at Woodgrove itself: we know those names, so we can tell customers right away when a name doesn't match."
>
> — Product owner, Payments

## What to build

A new module `src/payee.js` (with the same UMD wrapper as the other files in `src/`) that exports:

```js
verifyPayee(iban, name)
// → { result: 'MATCH' | 'CLOSE_MATCH' | 'NO_MATCH' | 'NOT_POSSIBLE', suggestedName? }
```

It looks up the account holder in `data/accounts.js` (`Woodgrove.accounts`).

- Case, accents and extra spaces are ignored: `JAN  DE VRIES` is a `MATCH` for `Jan de Vries`, and `Emilie van den Berg` is a `MATCH` for `Émilie van den Berg`.
- Initials (`J. de Vries` for `Jan de Vries`) or at most 2 typos give `CLOSE_MATCH`, with the holder's name as `suggestedName`.
- Anything else is `NO_MATCH`.
- An IBAN that isn't a Woodgrove account gives `NOT_POSSIBLE`.

The transfer console shows the result under the beneficiary name field, for example:
✅ Name matches · ⚠️ Did you mean Jan de Vries? · ❌ Name doesn't match this account · ℹ️ Name check not possible for this bank.

## Examples

| IBAN | Name | Result |
|---|---|---|
| `NL20WGBK0123456789` | `Jan de Vries` | `MATCH` |
| `NL20WGBK0123456789` | `J. de Vries` | `CLOSE_MATCH`, suggestedName `Jan de Vries` |
| `NL20WGBK0123456789` | `Jan de Vris` | `CLOSE_MATCH`, suggestedName `Jan de Vries` |
| `NL20WGBK0123456789` | `Piet Jansen` | `NO_MATCH` |
| `FR76 3000 6000 0112 3456 7890 189` (any French IBAN) | `Claire Dubois` | `NOT_POSSIBLE` |
