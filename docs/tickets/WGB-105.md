# WGB-105 · API documentation

**Type:** Documentation · **Priority:** Medium · **Component:** `server.js`, `docs/`

## Story

> "The mobile team wants to call the Woodgrove Transfers API next sprint. Right now the only documentation is the code in server.js. Can we give them a proper reference?"
>
> — Engineering lead, Payments

## What to write

A new file `docs/api.md` with:

- How to start the API (`node server.js`, port 3000 by default, `PORT` to change it).
- An endpoint reference for `GET /health`, `GET /ibans/:iban` and `POST /transfers`: purpose, request, response, status codes, and an example request (`curl`) and response for each.
- A table of all error codes (validation errors and HTTP errors) with their meaning.
- A Mermaid sequence diagram of `POST /transfers`: client → server → validation → response.

## Acceptance criteria

- [ ] Every endpoint in `server.js` is documented, with examples that match what the code really returns.
- [ ] Every error code in `src/transfer.js` and `server.js` is in the table.
- [ ] The Mermaid diagram renders on github.com.
